# Snake Club v0.0.2 开发计划

## 目标

把 v0.0.1 的 Canvas 贪吃蛇升级为基于 Unity 的俯视角 3D 大地图对战游戏。首要发布目标是抖音小游戏；浏览器 WebGL 用于本地开发和验证。当前仓库只保留 Unity 游戏实现；旧版可从 Git 历史中查看。

## 玩法

- 地图采用连续移动的大型竞技场，镜头跟随玩家，并提供边界、对手方向和小地图信息。手机以虚拟摇杆和加速按钮操作，浏览器额外支持键盘和鼠标。
- 地图中分布可收集的果实，吃到果实可以少量成长，但对抗其他蛇是核心。蛇头撞到其他蛇的身体时，撞击者被淘汰，幸存对手直接吸收其部分长度并增长；蛇头相撞时较长的一方获胜，等长时双方淘汰。碰到地图边界时反弹，不会因此失败。
- 允许短时加速，加速消耗自身长度；出生时提供短暂无敌，避免刚进入就被淘汰。采用限时回合，提前决出最后幸存者时结束；时间到按长度和击杀情况结算。
- **PvE**：单机运行，玩家与多个 AI 蛇对战，不依赖服务器。
- **PvP**：真人房间对战，通过房间号加入可配置的服务器，房间内不注入 AI。
- **混合**：真人和 AI 在同一服务器房间中对战；服务端负责所有蛇的移动、碰撞、成长和结算。
- 画面采用有层次的竞技场、立体蛇身、清晰的玩家标识、死亡反馈和方向提示；优先保证移动端性能和可读性。

## 技术方案

- 新建独立 Unity 工程，采用 Unity 6 LTS 的安全更新版本和 WebGL 构建支持；游戏逻辑尽量避免依赖特定 Editor 版本，实际抖音转换兼容性必须验证。
- 将移动、碰撞、积分、AI 和房间规则实现为可独立运行的纯 C# 模拟核心；Unity 客户端的离线 PvE 和权威服务器复用同一份规则，避免两套逻辑偏离。
- 真人联机需要对局协调与实时状态同步，但无需自行购置服务器：优先考虑抖音云托管，也保留可配置的自建服务。抖音云的 WebSocket 网关文档明确写明不适用于小游戏，因此不能假定其 connectContainer 网关可用于本项目；云托管直接对外提供 WebSocket 的入口和部署可行性须在开通后实测。先在本地运行 .NET WebSocket 房间服务并验证，暂不购买、开通或部署云资源。服务端采用固定频率权威模拟，校验房间、输入频率和方向；断线有明确反馈，不把 AI 伪装成真人。
- Unity 编辑器/桌面端使用原生 WebSocket 客户端，WebGL 通过浏览器 JavaScript 桥接。服务器地址、房间号和模式可配置；默认仅用于本地开发。公开联机需另行部署可访问的服务与 WSS，不假设已有公网基础设施。
- 抖音目标采用官方 Unity WebGL 转换工具及其 C# SDK；先验证普通浏览器构建，再验证抖音开发者工具和真机。官方新包体支持引擎切换，但现有小游戏的具体切换资格、账号权限、AppID、CDN 和域名配置以平台实际要求为准。
- 安装所需的 Unity Hub、Unity Editor/WebGL 支持及 .NET SDK；账号登录、许可证或平台账号授权由实际界面要求决定。许可证和凭据不写入仓库。

## 开发顺序

1. 写入本计划，确认联机方式和平台范围，检查并准备本机工具链。
2. 实现可独立测试的竞技场规则：移动、蛇身轨迹、碰撞、成长、加速、AI、边界和结算。
3. 实现权威房间服务器，以及房间创建、加入、断线和状态同步；覆盖 PvP 与混合房间。
4. 创建 Unity 3D 场景和完整游戏界面，接入 PvE 与联机客户端，适配竖屏触摸、桌面输入、镜头和小地图。
5. 实现可重复构建流程及运行说明；先验证 Unity 编辑器/桌面、浏览器 WebGL，再接入和验证抖音转换。
6. 更新 README 和验证记录，说明实际完成情况及仍依赖的账号、服务端部署或平台权限。

## 验收标准

- Unity 工程可被指定版本的 Editor 打开，项目编译无错误；场景可以进入菜单并启动一局。
- PvE 无网络可开始、对战并结算；地图明显大于屏幕，玩家移动时镜头跟随。
- 两个独立客户端能通过同一服务端和房间号进入 PvP；混合模式中真人与 AI 共享同一权威战场。不能联网时明确报错。
- 对手碰撞、相互碰头、果实成长、加速消耗、出生保护、击杀成长、边界反弹和回合结算有自动化验证；房间和多人状态同步有集成验证。
- WebGL 在浏览器可运行，并验证其与房间服务器的连接；抖音产物仅在官方转换和开发者工具实测成功后标记为可用。
- 不上传、发布或申请平台资源；项目中的示例地址和开发服务器不包含凭据。默认构建入口指向 Unity WebGL。

## 后续玩法建议

- **竞技区域**：定时出现限时争夺区或移动热点，吸引远距离对手交战；保留撞墙反弹规则，避免玩家因地图边界直接失败。
- **风险与收益**：加速消耗长度，击杀后提供短暂保护或有限的连击奖励，让追击与撤退都有选择，并限制领先玩家无限滚雪球。
- **场景变化**：加入可反弹的障碍、加速通道或传送区域，让大地图不仅是空旷平面；先用少量可读性强的障碍验证手感。
- **多人玩法**：提供限时生存、击杀积分和双人组队等房间规则，混合房间始终明确标识 AI 与真人。
- **失败后的参与**：加入自由观战、击杀回放和对局数据；另设可复活娱乐模式，避免朋友提早出局后长时间等待。
- **长期目标**：提供皮肤、蛇身轨迹、表情和短期挑战等纯展示奖励，避免影响对战公平。
- 根据真实数据迭代 AI 难度、出生保护、单局时长和匹配人数；公共匹配、赛季排行与好友系统在服务部署和账号体系成熟后再做。
