# v0.0.3.4 高优先级体验优化：玩家优势与成长视野

> 状态：**待设计、开发和验收**。2026-11-19 根据实际试玩反馈新增；以下两项均为高优先级，优先于新增角色和次级玩法扩展。优先针对抖音小游戏的默认强弱吞食试玩；本文不代表功能已经实现。
>
> 本文在冲突处更新 [v0.0.3.1](v0.0.3.1.opt.md)、[v0.0.3.2](v0.0.3.2.opt.md) 和 [v0.0.3.3 强弱模型](v0.0.3.3.strength-model.md) 的新版本目标：普通单人试玩需要给予玩家实际可感知的优势，而不是坚持玩家与 AI 在所有条件下完全对称。历史模式、已签发的对局和日榜回放不得直接套用新规则。

## P0：给玩家实际优势，让人有机会吃到东西

**用户反馈**：体验太差，经常什么都没吃到就被吃了。需要给玩家加入特权，改善开局和整局体验，而不是只增加文字提示。

**当前事实**：默认强弱试玩中玩家和 AI 使用统一基础属性，首局玩家出生保护 4 秒、AI 3 秒，后续普通对局均为 3 秒；身体吞食、头碰头、局内等级和增益规则见 [v0.0.3.3](v0.0.3.3.strength-model.md)。现有保护不能视为已满足这次反馈。那里的固定输入诊断存在玩家存活和吞食不足的迹象，但不能代替真人数据。

**必须实现的结果**：默认普通单人强弱试玩的玩家每局都能获得实质优势，不只在第一次游戏生效；要让玩家在开局有可达的成长资源和合理的试探、吞食与反击机会，减少尚未体验吞食就被连续压制或淘汰的情况。优势需真实作用于规则或机会、可理解且可见，不以付费、广告或额外按钮作为前提。玩家仍能失败，但应能看懂原因并愿意再试。

首轮设计和实现按以下顺序推进，具体参数及组合通过测试确定，不把候选值当成已经完成：

1. **可成长的安全开局**：保证玩家出生附近有足够且真实可拾取的果实，以及可追到、可交互的较弱目标；检查边界、生成间距和移动可达性，避免被 AI 立即抢光。保护期应有明确的开始和结束反馈，并避免出现“看似可以吃、实际双方受保护无法接触”的误导。
2. **玩家专属局内特权**：设计可实际影响交锋的限时／有限次优势，例如初始攻防加成、首次遭遇减损或挽救机会；明确生效条件、持续时间／次数、消耗、冷却和视觉提示，不能靠假碰撞或偷偷改结果实现。特权不仅用于首局，普通试玩每局都有可用的玩家优势；首局可以再叠加经过验证的新手辅助。
3. **持续的回追机会**：评估落后时有限的追赶资源或临时保护，避免一旦被吃就只能不断被追着吃；设置上限和退出条件，防止无限无敌或成长滚雪球。AI 的出生、追逐、避险和攻击节奏须与上述特权一起调试，确保仍有可理解的挑战。
4. **版本和边界**：玩家、AI 仍使用同一套强弱比较及身体从头到尾递减模型；玩家特权作为明确记录的额外状态／系数参与计算，而不是把强度不足的接触伪装成成功。触碰身体本身不直接失败。若特权改变模拟、输入、随机消耗或结算，新增规则版本并保持确定性重放，历史录像、已签发对局、奖励及日榜兼容。正式公平挑战、联网和付费模式的使用方式单独设计，不能无提示地改变其公平性。

**验证与验收**：

- [ ] 自动化覆盖特权触发、有效期和结束、消耗、叠加上限、出生保护、双方同时接触、头部和身体判定、重开、暂停／恢复及新旧规则隔离；实际吞食、伤害和特权提示一致。
- [ ] 相同种子比较调整前后，记录首个果实／身体吞食所需时间、未吃到身体就出局比例、早期存活率、每局吞食次数与胜率；覆盖不同操作策略，并标明脚本不等于真人。用结果调整或撤销无效方案，而不是以固定策略胜率替代体验验收。
- [ ] 用真实玩家及抖音手机试玩首局与多次普通局，观察是否理解特权、能否在前期吃到东西、失败是否可理解以及是否愿意再玩；记录机型、版本、样本和失败案例。

## P0：吃多变大，视野随成长自动拉远且可配置

**用户要求**：吃多之后自身要明显变大；视角范围随成长自动变大，同时在设置中支持配置视野范围的相对大小。

**当前事实**：强弱试玩的真实长度会增长，已有外观会根据头尾防御改变粗细和角色大小，但视觉表现仍需验证是否足够明显；镜头当前主要在加速时从约 20 调整至 22，并未按长度自适应，也没有相对视野设置。因此不能把已有长轨迹或强度外观当作这条需求已完成。

**实现要求**：

1. 将**本局实际成长**映射为玩家肉眼可辨认的体型变化：吃到果实或身体导致真实长度／成长增加时，身体长度、粗细和角色尺度协调变化；身体被吃或因加速损耗而缩短时，外观依据当前状态合理收缩，不以历史最高长度冒充当前大小。同一增长在不同角色和简洁特效下仍可辨认，不依赖头顶小数字；其他蛇也应按其真实成长表现，特权效果则有独立、可解释的反馈。
2. 以**当前玩家实际成长**驱动摄像机平滑拉远，并在缩小时平滑回收；叠加现有加速镜头效果时设定清楚的上下限和优先级。增长前后画面不能突然跳变、晃动、穿出场景或把角色缩得不可辨认；大蛇不要求始终在镜头内完整显示，但附近威胁、果实、方向和可接触身体应保持可读。死亡、结算、暂停／恢复、换局、观战和不同角色切换均需定义一致的镜头行为。
3. 在**设置**提供相对视野大小配置，以自动视野为基准提供有明确文字的较近／默认／较远或等效可调控件；用户可随时在对局中通过暂停／设置调整，也可在大厅配置。变更立即平滑生效、跨启动保存，默认值及边界经过手机试玩确定；无效或旧设置回退默认。偏好仅改变本机显示，不改变速度、强度、碰撞、随机过程或奖励。安全区和暂停／设置控件不能破坏正常全屏拖拽转向及双指加速。
4. **碰撞与显示一致性**：视觉体型放大不自动改变现有真实碰撞半径；保留清晰的实际碰撞圈、轨迹和接触反馈，避免让玩家误以为图案边缘就是判定范围。如果后续决定让体型也改变真实碰撞范围或段间距，必须单独完成强弱与碰撞数学设计、用户可见提示和规则版本兼容，再实施；不能通过仅改变图片悄悄宣称碰撞范围改变。
5. 调整相机后统一检查角色名牌、离屏箭头、小地图、果实、身体可吃金点、危险标记、UI 安全区及触控坐标；镜头偏好和成长不得造成标记漂移、明显遮挡或点击区域偏移。

**验证与验收**：

- [ ] 自动化覆盖最短／最长身体、增长和损失、不同强度及外观、加速叠加、相机边界、缩放平滑和设置读写；验证不同视野设置下碰撞、输入、回放结果完全不变。
- [ ] 以真实对局连续画面比较小蛇、中等、大蛇和缩短后的体型与镜头；验证不同屏幕比例、低画质和拥挤场景，观察角色辨识、近处威胁、UI 与标记。后台截图和模拟触摸可作为研发证据，不能代替抖音手机试玩。
- [ ] 在至少一台 Android 与一台 iPhone 的抖音环境验证三个视野偏好、设置持久化、暂停／锁屏恢复、手势及性能；记录具体机型、版本和问题。

## 优先执行顺序

先完成玩家优势方案和成长／视野曲线的可复现基线，再实现普通强弱试玩中的特权、体型与自动镜头及视野设置；随后运行规则、回放、UI 和设备验证，以真实试玩反馈调整。两项都要交付并验收，不能只完成设置或特效就关闭需求。
