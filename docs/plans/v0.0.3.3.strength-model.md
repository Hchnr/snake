## 目标与不可改变的要求

- 碰到对手身体或留下的轨迹本身不意味着失败。玩家比接触部位强时可以吃对方身体；比较的是当时、当地的实际强度。
- 强弱不只看长度：考虑长期成长、局内等级与长度、速度、身体硬度、局内随机因素，以及通过操作获取的临时收益。
- 身体不是全身统一强度：从头到尾逐步变弱，尾部更容易被吃。轨迹可表达身体位置和路径，但不是独立的致死墙；无实体的历史残影不得产生碰撞或吞食。
- 同一规则适用于玩家与 AI；成长、随机和操作状态必须可见、可解释，可重放。参数是试验起点，不是已经平衡或经过用户认可的结论。

## 术语、单位与分层

用整数定点表示强度，1000 = 1.000 倍；最终强度用「点」表示。每一模拟步（20 Hz）先冻结所有对象的同一份状态快照，再计算碰撞；渲染和音效不能改变计算结果。

| 层 | 建议输入与范围 | 持续时间 | 目的 |
| --- | --- | --- | --- |
| 固定成长 | 账号基础值 `P`（初始 100、随等级／养成增长）；硬度成长 `H`（0～300） | 跨局，服务端确认 | 长期目标；休闲模式使用上限和分段递减，避免新玩家完全无法交互。 |
| 局内成长 | 本局长度 `L`，初始 16、暂定上限 80；局内等级 `G` 由本局经验确定 | 本局 | 让吞食、淘汰和拾取带来及时变化，不把局内成长写成永久等级。 |
| 随机 | 场内可见、可争夺的增益物，种类、出现时间与位置由服务端种子和规则版本生成 | 有明确剩余时间或次数 | 局内变化，不在每次碰撞暗掷胜负；生成有频率和上限，AI 遵守相同规则。 |
| 操作 | 合法加速、闪避后反击、连续命中等可观察动作生成的短期收益 | 秒级或次数 | 鼓励技术；需要提示、冷却和叠加上限，不能用无成本连击无限滚雪球。 |

每日公平挑战应使用统一固定基础成长／硬度，局内成长、可见随机物和操作收益保留；普通模式可使用账号成长但要在匹配／难度设计中限制差距。皮肤默认仅改外观；如另有属性，必须明确展示，并统一受对应模式上限约束。

1. **基础攻防**：`B = clamp(P + 3 * G + floor(3 * max(0, L - 16) / 2), 100, 300)`。其中 `G` 由局内经验按离散阈值计算，限制为 0～20；对长度的收益线性但有总上限。`P` 的候选账号曲线和快照仅接入下述本机实验，尚未用于正式规则；不能直接把已有经验数值当成战力。
2. **身体位置**：头部序号为 0，尾部为 `L - 1`，`q = floor(1000 * i / max(1, L - 1))`。部位系数 `T(i) = 1000 - floor(450 * q / 1000)`，从头部 1000 逐渐下降到尾部 550；保留最小尾部系数，避免长蛇尾部永远一碰即断。可在测试后改为平滑曲线，但必须单调、尾部不强于头部。
3. **速度／姿态**：速度以当前实际速度 `v` 和该模式基础速度 `v0` 的整数比 `r = clamp(floor(1000*v/v0), 700, 1500)` 表示。主动、合法加速且速度确实高于基础时，头部攻击系数 `V = 1000 + min(120, floor(max(0, r-1000)*120/500))`；其他时候为 1000。墙反弹或速度受控时只按真实速度计算，不得把加速按钮本身当成成功命中；加速消耗和碰撞风险保留。身体防御不因对方速度降低。
4. **持久硬度与临时效果**：`D(i) = floor(B * T(i) / 1000) + floor(B * H / 1000)`；硬度加成先按全身加算以保留养成价值，但因 `T` 递减，各部位总体仍递减。临时增益与操作收益分别用 `R`、`O`（基点，默认 1000）表示；先限制各自在 850～1150、900～1200，再将 `M = clamp(floor(R*O/1000), 800, 1250)`。`攻 = floor(floor(B*V/1000)*M/1000)`，`防(i) = floor(D(i)*M/1000)`；双方各自的 `M` 独立计算。无增益时 `R=O=1000`。相同条件下攻击方头部比尾部更易成功，但并非保证必胜。
5. **判定缓冲带**：攻击大于防御的 105% 才是有效吞食：`攻*100 > 防*105`；差距不超过 5% 时安全弹开，弱于该范围也弹开并短暂分离，**不因碰到身体直接淘汰**。头碰头可另比较双方头部强度：高于 105% 者赢，缓冲带内双方弹开；此项与用户预期及节奏一起试玩后确定，不能先行视为定稿。比较采用 64 位整数并限制输入，避免溢出。

例：双方 `B=100`、`H=0`、无增益，攻击为 100；对方头部防御 100、尾部 55，攻击可吃尾部但头部差距不足则弹开。若对方 `H=300`，尾部防御为 85；若攻击方被弱化至 80，则不能吃该尾部，弹开。上述只是公式演示，不保证实际平衡。

**独立 v13 规则的本机回放联调（2026-11-20）**：新增独立的无奖励实验，服务端签发随机种子并根据服务端账号状态固定首局配置，凭证绑定规则、开局时间、到期时间和快照；客户端按快照运行 `strength-local-advantage-13`，服务器只接受完整录制并比较终局摘要。首次真实转向前，录制方向必须保持默认向右；这只是录制格式检查，不能证明操作由真人产生。同一完成回执可重试，不修改玩家资产、排行或成长。该服务仅非生产环境显式开启，直接连接对端必须为回环地址；反向代理可能使外部请求表现为回环，实验路径不得经未隔离代理暴露。客户端仅显式本机开发配置可用，TTSDK 玩家构建强制关闭；本地离线首局状态与服务端快照分别保存。

## 一次接触如何吃身体

- 只检测头部与对方**当前有效身体段**；排除自身、无效残影、已死亡对象和出生保护中的双方。身体段编号及长度均来自同一快照。
- 第一版候选：成功命中某段时，先按快照从命中段开始、向尾部检查最多 3 个相邻段，逐段比较防御；只有符合强度条件的连续命中段被移除并按实际数量给攻击方成长，剩余身体段沿原顺序衔接。若被命中部位更强但尾部更弱，**不允许隔空吃尾巴**；命中段必须先通过比较。被吃者保留最短身体和完整头部，直到头部按另一套明示规则被击败；避免一次触尾就无缘由消灭整条蛇。具体截断方向、每次数量、最短长度和收益待试玩调整。
- 同一攻击者与防守者设置短暂命中冷却（候选 0.4 秒）和实际分离，防止帧率影响连续吞食；冷却、弹开、保护都不伪造吞食效果。加速是否让身体损耗与吞食叠加，按同一快照逐项算清。
- 同一步多个攻击者碰同一身体、双方互相接触、头碰头与身体命中同时发生时：收集所有事件 → 根据快照计算强度 → 头部冲突优先 → 对同一身体段按更大有效强度优势、再稳定 ID 排序去重 → 同时应用每条蛇的身体损耗 → 按仍存活的攻击者和实际损耗发成长 → 处理回弹及结束。不得依赖列表遍历顺序，互相吃身体应有确定结果。需用表驱动和置换测试验证。
- **多人同帧命中离线候选 v11**：原 v10 为防索引错乱，每条防守蛇每步最多被一名攻击者吃到，较本节按身体段去重的目标更严格。v11 按同一快照的实际强度优势、稳定角色 ID 分配不重叠的连续段与最短长度预算；接触段已被更高优先级占用时，不能跳过它吃后面的段。每个攻击者每步仍最多吃一次；各蛇损耗统一结算后再按实际数量增长。被吃部位在同帧全部按原快照删除，剩余段重新衔接；弱接触弹开会检查被命中段是否仍存在且实际接触。玩家多处同时受伤时合计数量，并在各个真实受伤位置显示短暂提示圈。
- **验证与限制**：桌面回归覆盖非重叠、重叠截断、最短长度、事件顺序、删除后弹开映射、满长度互吃，以及玩家同时攻击、双处受伤与回追补给。v10 逐步状态金标准保持一致；112 组 v11 样本及人工布置的真实双重受伤夹具在桌面 .NET 与无头 Unity WebGL 对照一致。另一局 1200 步无头浏览器模拟全屏拖动和双指加速，实际输入在 v11 内存重放与桌面终局摘要一致；该局不保证发生多人同帧命中。一张 540 × 960 无头竖屏画面使用人工三蛇布局、真实双重受伤步骤并冻结时间，两处受伤圈部分被立绘和蛇身遮挡；不能据此认定动态反馈在自然对局中清晰。v11 仅用于离线无奖励强弱试玩，不改服务端实验、正式奖励和旧版规则；上述样本不是抖音真机、全输入覆盖或真人体验验收，录像持久化与导入仍未作为玩家功能提供。
- 围圈原型已作为待验证的操作收益：不能绕过“更强”的条件直接淘汰。候选是闭合时对圈内目标产生短暂可见压制或操作加成，再按照同一强度规则接触吞食；强弱差过大时应给清楚反馈。是否保留、具体幅度和收益等待 A/B 试玩，不改变旧榜规则。

## 例外、公平与可读性

- 出生保护使双方暂不可互相吞食，保护倒计时结束明确提示；保护不让角色无提示地得到永久强度。
- 随机物在生成前后均有可观察提示，效果、剩余时间和叠加上限可查；相同种子、规则版本和输入产生相同结果。不可用未公开的概率在接触时偷偷改写胜负。
- 用颜色之外的形状／图标、身体分段与明确提示表达“能吃／相近／更强”，低画质和色弱下保留关键信息。碰撞范围以真实几何为准，不能让装饰或残影变成隐藏判定。
- 在失联、后台、重复提交和跨账号时，客户端不得授予正式奖励；服务端需验证开局快照、版本化输入和实际时长。局内可先做不发奖励的离线原型。

## 实施和验收顺序

1. 在隔离实验模式中实现版本化整数强度计算、分段状态与可解释的吞食结果；先补公式边界、身体位置单调性、对称性、同帧排序、保护、冷却、最短长度、截断／重复输入和溢出测试。
2. 接入玩家及 AI 相同的身体吞食、分段外观、攻防提示和真实成长反馈；移除新模式里“碰到轨迹即死”的危险提示、教学、淘汰理由和 AI 回避逻辑。旧版回放与历史榜继续走原规则。
3. 建立服务端签名种子、成长快照、固定规则版本和跨目标回放，完成完整记录、旧数据兼容、幂等结算、抖音设备及弱网验证后，再评估是否允许正式奖励。
4. 用真实对局及同一设备的 A/B 原型比较：首局理解、能否吃尾、较弱方是否有反击机会、随机／操作收益是否可读、平均对局长度、滚雪球和再玩意愿；记录样本、参数和失败原因。按结果调参，不把脚本胜率视为玩家体验。
5. 首页现先提供不计账号奖励或排行的强弱吞食试玩，旧版围猎和日榜保留为明确标识的历史规则入口；完成真实玩家、设备和服务端验收后再接入正式账号奖励及新版本日榜，不改写 `daily-1` 至 `daily-4` 的历史成绩与已签发凭证。
