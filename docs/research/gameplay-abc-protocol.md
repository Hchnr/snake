# 围猎玩法 A/B/C 试玩记录

状态：**尚未招募、尚无试玩结果**。本记录配合 `v0.0.3.2.opt.md` 第 4.5 节，用于观察玩家是否理解并愿意再玩；不能用脚本通过率代替真人反馈。

## 准备

- 使用同一离线对照构建、设备、角色、画质和音量；在同一北京时间日期完成一位参与者的三个方案，避免日期种子变化。记录构建提交、设备、日期和每局是否完整。
- A 是历史 `daily-2`；B 是 `daily-4` 收圈；C 与 B 同开局和事件，但关闭收圈。A 的初始长度和出生距离不同，分析 A 与其他方案时要标明这一混杂因素，不能把全部差异归因于收圈。
- 建议按 ABC、BCA、CAB、ACB、CBA、BAC 六种顺序轮换分配；记录实际顺序。不要告诉参与者各方案的规则差异或预期答案。
- 每个方案玩一局，允许自然结束或自主退出；试玩中不口头解释规则，遇到无法继续操作则记录并允许退出。观察员不代替玩家操作。

## 每局记录

| 字段 | 记录方式 |
| --- | --- |
| 参与者编号、顺序、方案 | 使用编号，不记录姓名或联系方式 |
| 构建、设备、北京时间日期 | 记录实际值；跨日则注明 |
| 完整 / 提前退出 / 故障 | 记录原因和发生时机 |
| 操作理解 | 不提示地问「你怎样控制？角色、轨迹和对手是什么关系？」记录原话及是否基本说对 |
| 合围理解 | 问「刚才发生了什么？你为什么成功或失败？」记录原话；A/C 没有收圈，不应被计为失败捕获 |
| 关键事件 | 记录真实闭合、捕获、误触、看不懂和出局原因；无法观察时填未知 |
| 再玩意愿 | 问「如果现在可以选，你愿不愿意再玩这一版？」记录是 / 否 / 不确定及原话 |

三局结束后，问参与者更愿意重玩哪一版以及原因；先记录原话，再解释各方案差异。不要把观察员对正确答案的判断当作参与者的表述。

## 汇总

分别列出每个方案有效试玩人数、能说清角色与轨迹关系的人数、真实闭合和误解人数、再玩意愿的分布及代表性原话。按实际有效人数报告分母，不将缺失或中途退出自动记为成功。目标样本为至少 20 名目标用户；样本不足只作探索。按照计划，B 的理解率目标为至少 75%，且再玩意愿和成功 / 失败原因的理解不低于 A、C；达不到时先修正规则或回退，不将方案视为已验收。
